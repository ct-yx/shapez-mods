# Factory Area Snapshot / 工厂区域截图

> 对工厂中已放置机器的实际边界自动加留白，以普通镜头的渲染路径分块拼接为一张高分辨率 PNG。

- **分类：**视图 / 工具
- **版本：**1.8.0
- **文件：**[`factory-area-screenshot.js`](../../mods/factory-area-screenshot.js)

## 用途

`Factory Area Snapshot` 用于保存整片工厂的清晰布局图。它不是地图总览截图：每一块都走游戏普通镜头所使用的地图背景、传送带物品、建筑前景和 Hub 绘制顺序，因此建筑、传送带与物品的样式与正常游戏画面保持一致。

截图支持两种范围：默认会扫描普通层中所有已放置机器，计算最小外接矩形并在四个方向增加可设置的留白；也可以先进入地图总览，用左键拖拽矩形框选任意区域。默认机器范围留白为 **4 格**，适合保留外围传送带、地下带出口和构图呼吸空间；地图总览选区则严格按拖拽矩形导出。

## 核心功能

- **左上角独立入口：**进入存档后，左上角出现「截图」按钮；展开的面板不会占用原版工具栏格子。
- **机器区域自动检测：**以普通层 `StaticMapEntity` 的实际格子范围为基础；不会因地图总览可加载范围而扩大截图。
- **四边等距留白：**机器范围模式可设置 `0–32` 格，默认 `4` 格；左、右、上、下均同时扩张。
- **地图总览框选：**点击「选择地图区域」，缩小进入地图总览后用左键拖拽矩形；框选可包含空白区域和任意局部布局，并按精确格子范围导出。
- **普通镜头分层绘制：**每块按“地图背景 → 传送带物品 → 建筑前景 → Hub”顺序绘制，不采用地图总览的剪影样式。
- **基准密度分区（最高 1024 块）：**以已验证的旧版 256 MP 截图为基准：该图约分为 30 个普通镜头分区，因此每个分区约对应 8.533 MP 的输出预算。后续导出按 `ceil(实际输出 MP × 30 ÷ 256)` 计算目标分区数，再按横竖比微调为可用的行 × 列网格：256 MP 约 30 块、512 MP 约 60 块、1024 MP 约 120 块。分区数硬上限为 1024 块。
- **清晰源与最终合成：**默认开启清晰像素采样。最终倍率高于 1× 时，每个分区先以原生清晰源倍率走普通镜头绘制流程，再以最近邻方式合成到最终输出尺寸，避免同一精灵图集被游戏平滑路径再次放大而变糊；关闭该选项则恢复游戏的直接倍率绘制。
- **智能稀疏分区：**默认开启。Mod 会根据普通层的已放置实体建立分区热度图：包含机器、传送带或 Hub 的分区保持完整清晰源倍率；未放置机器的空白/原生区域以较低源倍率绘制后再最近邻合成。最终图片尺寸不变，稀疏区域的重复像素更多，渲染工作和 PNG 编码数据量都会降低。
- **动态缓存与单次编码：**较小图片使用最终画布直接拼接；实际输出达到 96 MP 以上、或任一边超过 16384 px 时，自动切换为条带缓存和流式 PNG 编码，不再常驻整张最终 Canvas。所有分区仍写入同一个 PNG 压缩流；条带会按输出宽度自动缩小，避免超宽图的缓存失控。渲染过程中会让出浏览器事件循环，可取消。
- **边缘重叠缓冲：**每块带有额外绘制边缘，再只拼接核心区域，防止大型建筑、物品或传送带在分块交界处被截断。
- **输出限制与自动降倍率：**只保留一个 16–1024 MP 的目标分辨率选项；Mod 会按当前截图区域自动计算渲染倍率，并尽量填满该分辨率，不会出现“1× / 2× 被同一预算压成同一输出”的重复控制。支持流式 PNG 时，超大截图可放宽到 65535 px 单边；否则仍保留 16384 px 的兼容限制。
- **一致帧导出：**可在截图期间暂停模拟；完成、错误或取消后都会恢复原来的游戏速度和原先图层。

## 使用方法

1. 启用 Mod 并进入一个正在运行的存档。
2. 点击左上角的「截图」，按需要选择范围：
   - 点击 **机器范围**：自动扫描机器边界并应用外围留白。
   - 点击 **选择地图区域**：缩小进入地图总览，再用左键拖拽框选任意矩形。
3. 确认面板中的“机器范围 / 地图选区”“截图范围”“输出尺寸”“清晰源 / 最终倍率”和“分区捕获”。分区项会同时显示实际行 × 列和按 256 MP 基准计算的目标数。
4. 按需要调整：
   - **外围留白：**默认 4 格；仅机器范围模式使用，用于让工厂边缘与图片边缘隔开距离。地图选区严格按拖拽区域导出。
   - **目标分辨率：**唯一的清晰度控制。默认 64 MP；大型工厂可先用 16–32 MP 验证范围，再选择 256 MP、512 MP 或 1024 MP 导出最终图。面板会显示只读的“自动计算倍率”和最终输出尺寸。
   - **智能稀疏分区：**默认建议保持开启；如果需要让纯原生地形也以完整源倍率保留细节，可关闭该开关。
   - **包含传送带上的物品：**关闭后只导出静态布局，速度更稳定。
   - **渲染期间暂停模拟：**默认开启，保证拼接后的每块处于相同模拟时刻。
5. 点击 **导出 PNG**。浏览器完成编码后会自动下载 `factory-area-snapshot-时间.png`。

## 性能与限制

- 64 MP 以下会使用最终 RGBA Canvas，64 MP 约需 256 MB 原始像素内存。实际输出达到 96 MP、或任一边超过 16384 px 时，支持 `CompressionStream` 的游戏运行环境会自动改用条带缓存：常驻的像素工作集约为“按宽度动态限制的当前条带 + 一个渲染块”，而不是整张图片。最终 PNG 文件仍按内容压缩，机器稀疏、背景重复时通常很小。
- 分区绘制与最近邻合成使用 GPU-preferred 的 Canvas 2D 上下文；仅在流式 PNG 编码时把当前块复制到独立的 CPU 读回画布。PNG 行编码、压缩和文件写出本身必须在 CPU 上完成；游戏的地图绘制 API 共享单一 Canvas 2D 状态，因此地图绘制保持串行以保证去重、绘制顺序与画面正确，不能安全地并行调用。
- 流式路径的最终图片单边上限为 65535 px，图片总像素上限不超过所选预算（最高 1024 MP）；若运行环境缺少流式压缩接口，则自动使用最终 Canvas 路径，并保留 16384 px 单边兼容上限。
- 面积或长宽比过大时，分析结果会显示根据单边上限自动调整后的“自动计算倍率”和最终输出尺寸；此倍率为结果信息，不是额外设置项。
- 默认始终导出**普通工厂层**。地图总览只用于选择区域，不会进入地图总览剪影绘制；即使当前正在查看线路层，导出过程中会暂时使用普通层，结束后恢复原图层。
- 启用 `structured-mod-settings.js` 时，同一组参数也会显示在 **设置 → 游戏模组（MODS）→ 工厂区域截图**；不启用前置时，左上角面板中的参数仍然完整可用。

## 兼容性

- 不修改物流、建筑属性或存档数据，`doesNotAffectSavegame: true`。
- 与 `Zoom out before Mapmode`、`Factory Stress Lab` 可同时使用；截图使用独立的临时画布，不改变当前相机位置、缩放或地图总览范围。
- 其他修改普通层绘制顺序的 Mod 会反映在截图中，因为本 Mod 调用的是游戏当前的普通层渲染系统。
